# 长时间生成与批量任务

> 上级：[用户指南](./README.zh-CN.md)

[English](./image-jobs.md) | 简体中文

Codex Plugin 的 API Key 生成、编辑和批量操作会先保存任务并返回任务 ID，再逐项生成图片。Codex 可以持续查询进度、显示已完成结果，无需让一次工具调用等待整批图片生成。ChatGPT 宿主生图与 Standalone 命令行仍使用各自原有流程。

## 提交和查看结果

像平常一样说明图片需求，例如“生成 40 张不同植物的图标，每张分别保存”。Codex 会为这次请求保留提交键和任务 ID，查询任务直到结束，并分组展示全部成功结果。

单个批次最多包含 64 项，总图片数最多 64 张。并发可以设为 1–8；省略时使用用户配置中的默认值。一次生成多个同主题候选图时，候选仍按顺序请求，并在整组成功后保存。

## 等待超时后继续

工具等待超时不代表生成失败，也不代表没有计费。可以告诉 Codex：“查询刚才的图片任务，继续显示结果，不要重新生成。”

请让 Codex 使用上次保存的任务信息找回结果。重复同一请求不能通过换一个提交键来绕过恢复流程，否则可能再次生成并计费。

任务状态和已确认结果保存在当前图片产物目录中。重启 Plugin 后仍可查询；执行中断的项可能需要最多 60 秒才能被识别。恢复需使用原项目、产物目录和图片配置。

| 状态 | 可以做什么 |
| --- | --- |
| 排队中、执行中 | 继续查询同一任务 |
| 成功 | 查看已保存图片，或继续编辑 |
| 本地处理失败 | 保留原图，恢复本地处理，无需再次请求图片服务 |
| 执行中断 | 恢复未发出的项，以及已有原图的本地处理 |
| 结果未知 | 保留任务信息，核对供应商的请求记录；不要直接重新生成 |

需要恢复时，可以说：“继续上次中断的任务，只恢复未发出的项和已有原图的本地处理。”恢复不会重发失败或结果未知的图片请求。

## 取消及限制

要求 Codex 取消任务时，Plugin 会停止排队中的项。已经执行的项，包括整组候选图，仍可能完成并产生费用；已保存图片不会删除。停止一次查询只结束等待，不会取消生成任务。

Plugin 退出会中断执行，已保存结果仍可恢复。如果图片已保存但任务尚未登记结果，重启后可能显示“结果未知”。Plugin 无法撤回已经到达供应商的请求，也不会为找回结果自动重新生成。

## 过程预览与最终交付

在 Codex Plugin 的 API Key 和 ChatGPT 路线中，图片可以分阶段生成、修改或处理。你可以中途查看进度，也可以在最终回复中集中查看需要交付的图片。需要选择方案时，供你比较的候选图会一起展示。中途看过的图片仍可出现在最终回复中；复用已保存的图片不会再次生成。

交付内容包括你要求的独立素材和仍需比较的候选图，优先使用修改后的最终版本及处理成功的图片。参考图、试验图和被替代的旧稿通常不展示；需要前后对比时，可以要求保留。结果按顺序排列，超过十张时分组展示。每张图片都有自己的画布入口，但已销毁的画布无法重新打开。

多张结果的预览会保留完整图片比例；结果区高度受限时，可在其中滚动查看后续卡片。点击图片可放大预览，点击 **打开画布** 可继续编辑。

如果只有部分图片成功，Codex 会说明缺少哪些结果。本地处理失败但原图仍可使用时，可以先查看原图，并了解尚未满足的尺寸、透明背景或其他要求。如果结果卡没有加载出图片，请让 Codex 检查已保存的结果，或参见[故障排查](./troubleshooting.zh-CN.md)。显示已有结果无需重新生成图片。
